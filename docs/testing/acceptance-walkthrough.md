## Automated browser cases

The XFSC Executor/Behave pack contains runtime/isolation and deployment lifecycle tests, plus browser configuration drafts, typed persistent validation errors, journey ordering/preview/publish, settings layout, invalid connector rejection, archive and a native offer journey. `administration.feature` and `offer.feature` mutate only the explicitly selected test tenant and require `PCI_BDD_ALLOW_MUTATIONS=1`. Configure `issuerKey`, `offerConfigurationName` and optional `journeyAnswers` in the private environment file. Captured browser sessions must be current.

```bash
PCI_BDD_ALLOW_MUTATIONS=1 /private/pci-bdd/bin/behave test/bdd/features \
  --tags='ux or offer' --junit --junit-directory /private/pci-evidence/ux
```

These cases use real APIs through the browser and fail on an upstream error. They do not fabricate wallet import, IdP authentication or accessibility certification. Registration/MFA/Entra/PCM journeys and cross-cloud results require their actual systems; use the matrix above and retain the resulting evidence. Do not enable browser trace/video recording of tokens, offers or credentials in a shared test report.
