# 0.5.0-rc.4 source remediation

This candidate implements changes for all eight findings in the supplied rc.3 review. It is not a zero-gap sign-off: live interoperability, the legacy helper baseline, required toolchains and owner/public obligations remain unverified or outstanding.

| Finding | Change | Local evidence / remaining validation |
|---|---|---|
| 01 Ambiguous revocation | Durable intent, immediate reissuance block, lease, correlated native readback, retry/backoff, restart recovery, guarded unblock and UI retry | Four recovery/concurrency regressions; real native lost-ack test pending |
| 02 Native SD-JWT | Use TSA `signer.signToken`; format-specific `typ`, salted disclosures, local cryptographic verification, single empty separator | Both profiles, tampering and holder-binding regressions; native/PCM matrix pending |
| 03 W3C claim paths | `credentialSubject` paths for W3C formats; root paths for SD-JWT; coordinated Draft 13 conversion | Metadata and profile regressions |
| 04 Tenant IAM settings | Versioned tenant-admin UI/API, fixed tenant alias, Kubernetes credential store, native admin recovery, signed broker admission, principal-only auto-enrollment, session invalidation | Config/secret/isolation/discovery regressions; fresh IdP/MFA/physical passkey acceptance pending |
| 05 Helper tenant cleanup | Register namespace identity and narrowly scoped deletion permissions; wait for namespace GC; remove cleanup role/binding before removing parent | Ownership, replacement, retry and UID precondition regressions; cluster acceptance pending |
| 06 Helper uninstall restoration | Journal prior/applied env, mounts and volumes; CAS restoration; protect foreign references; UID-guarded helper trust cleanup | Actual Python planner + Node restoration regression; legacy rc.3 baseline is not reconstructible without operator records |
| 07 BDD coverage | Fresh login/MFA/passkey, provider configuration, UI grant/revoke, participant-admin deletion, all advertised issuance formats, two-tenant/two-principal PCM display scenarios | Binding catalogue validated; actual Executor/device runs pending |
| 08 Linked-data algorithm metadata | Advertise `JsonWebSignature2020`, publish matching JSON-LD context, validate signed fields; add reference participant native LDP signer | Metadata regression; Go build and native LDP interoperability pending |

The reference participant now offers a separately configured native TSA linked-data signing path alongside Core JWT/SD-JWT signing. It enforces the configured issuer origin and verified TLS 1.3; PCI independently verifies returned credentials. This Go path has authored tests but has not been compiled in the authoring environment.
