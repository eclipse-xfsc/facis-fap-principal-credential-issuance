# 0.5.0-rc.11

## Exact tenant key identifiers in public JWKS

The operator confirmed rc.10 issuer and authorization discovery, successful TSA creation of `preauth` and `issuer`, and public availability of both EC P-256 keys. A software wallet obtained an access token and nonce with HTTP 200, then received HTTP 401 `invalid_token` from the credential endpoint. The native issuance log identified the exact mismatch: the token header requested `did:web:alpha-pci.example.com#preauth`, but public JWKS exposed the bare `preauth` identifier.

PCI now qualifies native TSA public key names with the published tenant DID. Already qualified IDs for that tenant remain unchanged. Foreign IDs, duplicate canonical IDs, malformed sets, symmetric keys and private key material fail closed with a sanitized 502. No key recreation, token modification, signature-validation bypass, shared OCM change or participant-image rebuild is involved.

Generated Function-node handler regressions perform real ES256 signing and public-key verification using exact full key IDs for both `preauth` and `issuer`. They cover input preservation, tenant headers, cache behavior and invalid-set rejection. Native HTTP and PostgreSQL boundaries are synthetic: this is local regression evidence, not successful live wallet issuance.
