# 0.5.0-rc.3

> Application change record. Checks and deployment observations below describe this revision at the time of release. For current container distribution and CI results, see [package 1.0.0](1.0.0.md) and [executed checks](completion.md).

This candidate extends rc.2 to close the locally implementable gaps identified by the requirement review. It includes code, generated ORCE artifacts, charts, tests and documentation. No public repository, registry, cluster or account was changed while preparing it.

| Area | Change |
|---|---|
| History | Authorized principal name/email search, distinct history-only JWT, verified holder-key DID, credential/status IDs and correct FR-81/82/83 mapping |
| Revocation | Reissuance blocked even for legacy configuration snapshots; explicit audited administrator unblock |
| Presentation | Draft 13 Presentation Exchange and 1.0 DCQL for holder-bound JWT W3C credentials; native issuer/status checks and volatile one-use sessions |
| UI | Expanded branding controls, corrected private registration mode, persistent safe errors and sanitized diagnostic frames |
| Deployment | Non-interactive release runner and importable operator ORCE flow; reversible flow/UI ownership tracking; complete guarded uninstall |
| Ownership/retry | Uninstall preserves later operator changes with UID/resource-version guards; repeated datasource setup retains its token and rolls out only changed records |
| Secrets/resources | Keycloak admin password moved from writable `/data` to a Secret mount; local credential export opt-in; bounded job/runtime resources |
| Transport | TLS 1.3 native HTTP/NATS clients, NATS upgrade/handshake-first support, verified database/SMTP client configuration |
| Native OCM | Version-bound empty-catalogue SQL patch plus existing payload-log patch proposals; feature opt-in requires owner-deployed fix |
| Tests | Real local TLS handshakes, automation/privacy/ownership regressions; expanded SQL test; browser job; live registration, lifecycle and two-profile/two-mode issuance/presentation/history/revocation pack |
| Documentation | Original specifications and hashes, AsciiDoc product document, editable UML sources, node contracts, every REST operation's request example, detailed acceptance boundaries |
| Semantics | Per-configuration JSON-LD/JSON Schema/SHACL export with scoped claim terms and synthetic examples; current issuer assignment is required |
| Release completeness | 101 SRS rows, 83 individual technical clauses and 120 REST request examples; obsolete generated API operations are removed; ArgoCD participant handoff is supplied |
| Credential encoding | Empty SD-JWT disclosure sets use the correct single separator; invalid ES256 signature scalars and missing signing context are rejected |
| Supply chain | Mailpit pinned to 1.31.4; documentation included in artifact identity; explicit opt-in Pages publication workflow |

See `validation.json` for the executed local result and its exact `notRun` list. New workflow files are not green workflow evidence. The Go/protobuf toolchain, Helm, PostgreSQL server and Chromium were unavailable locally; their authored checks remain unexecuted here. The deployment pack and software wallet require the operator's real environment.

The [completion report](completion.md) gives the exact development disposition and 198-test result, with build, owner and acceptance gates separated.

The strict all-endpoint TLS criterion still requires cluster-owner encryption of shared/native and compatibility chart paths. Supplied native patches require owner review/build/deployment. LDP/SD-JWT wallet interoperability is not proved, and VP supports only the explicitly advertised JWT format. PCM, Entra, accessibility, both clouds and public delivery remain acceptance gates. The sign-off tool continues to reject the unfilled receipt.

Use the [upgrade instructions](../operations/upgrade-0.5.0-rc.3.md), [automation](../operations/automation.md), [transport contract](../operations/transport.md) and [completion tests](../testing/completion.md). Restore from a reviewed backup for rollback; do not remove PVCs or reset database passwords to retry an upgrade.
