# 0.5.0-rc.7 — runtime readiness and installation retries

On the rc.6 cluster, UI and health returned HTTP 200, NATS was reachable,
the native listener reported connected, the Gateway was Programmed and internal
Keycloak discovery returned the correct issuer. Readiness nevertheless returned
503 because it expected `requestRaw().data`; that helper returns `text`.

The readiness check now parses discovery text and verifies the issuer. It still
requires PostgreSQL, platform state, the active native listener, the Programmed
Gateway, matching DNS and successful Keycloak discovery. Failures log only a
fixed check label; raw dependency errors and credential material remain private.
Regressions exercise the real HTTP helper over a local HTTP server, including
malformed JSON, wrong issuers and HTTP errors. This is regression evidence, not
the corrected live cluster's acceptance result.

`scripts/install-with-retries.py` provides five bounded installation attempts
with 5/10/20/30 second delays. Preparation transport failures can be retried.
Authentication, permission and certificate errors are rejected. Unknown errors
and failures after the flow deployment marker stop for inspection. The lifecycle
runner uses this helper for artifact installation; ground-zero and uninstall
are not automatically replayed. A temporary private kubeconfig and curl file
preserve the selected context, TLS verification and source files. Optional
explicit Gateway/API IPs support connection diagnosis without altering the
operator's kubeconfig. Records and logs are saved outside the release directory.

The source, rebuilt distribution, release metadata and regression tests ship
together. See [upgrade instructions](../operations/upgrade-0.5.0-rc.7.md) and
[local validation](validation.json). The retained [rc.6 compatibility changes](0.5.0-rc.6.md)
still apply. Native privacy, all-hop TLS and the full requirement acceptance
receipt remain existing gates; this readiness correction does not waive them.
