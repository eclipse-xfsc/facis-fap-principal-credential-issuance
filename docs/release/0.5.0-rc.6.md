# 0.5.0-rc.6 — OCM-WStack 12.3.9 compatibility

This release updates the complete rc.5 source for the supplied OCM-WStack ESB
12.3.9 package and incorporates the source corrections identified during the
rc.1 → rc.5 cluster upgrade. It is an integration candidate. It does not declare
unexecuted SRS acceptance, native owner changes or public-delivery obligations
complete.

## Behavior changes

- Crypto 2.3.7 linked-data verification omits obsolete tenant/group headers on
  its verify route, preserves the original credential bytes and sends a non-null
  disclosure frame. Signing and JWK scoping remain enforced.
- Issuance now requires a positive independent native status result before
  marking a credential issued or delivering it, for both signing modes and all
  credential formats. This is required because the new native LDP proof route
  does not verify revocation. Presentation also requires an explicit boolean
  positive status result. Unavailable and malformed verdicts fail closed.
- G0 migrates verified PCI Helm field ownership per object, with UID and
  resource-version guards. It resolves the password-path, RBAC rules and schema
  ConfigMap upgrade conflicts without a blanket force operation. Foreign
  releases and other field managers remain rejected.
- Native patch preparation is pinned to the current Crypto revision. It cannot
  build the old Crypto revision as a workaround. A supplied exact checkout and
  zero-fuzz patch context are required; original/result hashes are recorded at
  execution. Applying the privacy patch to the new revision remains unverified
  here. Historical checks are preserved separately.
- The lifecycle runner can resume `install-artifacts` using a private editor
  password file. Current Helm chart, deployment, API and documentation versions
  consistently identify rc.6. Historical SQL migration IDs are preserved.
